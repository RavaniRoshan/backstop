## Global Constraints

These bind every task. Violating any of them is a failed review.

1. **Preserve the in-process property.** No network hop on the request hot path. Backstop must
   still work fully offline with no key and no network.
2. **Preserve `~0.09ms` overhead class.** The ledger must not add blocking I/O to
   `BackstopTransport.handle_request`. The hot path may only do in-memory work plus a
   non-blocking `put_nowait` onto a bounded queue.
3. **Preserve the one-wrap-call adoption property.** `Backstop.wrap(client, budget=...)` must
   keep working unchanged. New capability is opt-in via config.
4. **Preserve the MIT license and the honest "What It Does Not Do" section.** Do not delete or
   weaken the honesty of that section. Qualify it where the code now differs.
5. **No new required runtime dependencies.** Standard library only for the ledger core.
   Anything else must be an existing extra or a new extra.
6. **Python 3.10+ compatibility.** No `match` on 3.11+-only features, no `typing.Self`,
   no PEP 695 generics. Use `from __future__ import annotations` where the file already does.
7. **Every behavioural change ships with a regression test.** A fix without a test that fails
   before the fix and passes after is not done.
8. **Every user-visible change gets a `CHANGELOG.md` entry** under `## [Unreleased]`, written
   for a reader who has not seen the code. State the behaviour, the reason, and the migration
   impact. No "misc fixes".
9. **Every README/docs claim must be verifiable.** If a claim cannot be verified by a command
   in the repo, remove it or qualify it.
10. **Zero credentials in code, logs, fixtures, or docs.** No API keys, no real customer data.
11. **Do not refactor unrelated code.** Touch only what a task requires. Pre-existing dead
    code discovered along the way is reported, not deleted, unless a task says otherwise.
12. **Async and sync must stay behaviourally identical** for every feature that is not
    explicitly documented as sync-only.

## Objective

Turn `backstop` from an in-process enforcement primitive into an in-process enforcement
primitive that also produces a **durable, priced, attributed spend ledger** — without
sacrificing any of the properties in Global Constraints.

After this build, a user can:

- run `backstop ledger demo` with no key and no network and see a real, priced,
  per-team chargeback table;
- attach attribution (`team`, `feature`, `customer`, `agent`, `task`, `env`, `repo`) to any
  call site with a two-line context manager and get those dimensions in the ledger;
- export a finance-grade chargeback CSV that joins to their own revenue data;
- get a runaway-spend detector with a shadow mode, so thresholds can be tuned before they bite.

## Task 1 — Correctness fixes

Five defects confirmed by the Step 0 audit. Each is a separate commit with its own test.

### 1a. Anthropic live-verify credential disclosure

`src/backstop/cli.py` declares `--api-key-env` with default `OPENAI_API_KEY` for **both**
providers, and `src/backstop/verify.py` reads that variable and sends it to the provider
endpoint. So `backstop verify --live --provider anthropic` sends the OpenAI key to Anthropic.

Fix: resolve the default key env var per provider. `openai` -> `OPENAI_API_KEY`,
`anthropic` -> `ANTHROPIC_API_KEY`. An explicit `--api-key-env` always wins. Never send a
credential to a provider other than the one selected. Test both the default resolution and the
explicit override without making a network call.

### 1b. Priority-gate ticket leak on timeout

`src/backstop/admission.py`: `acquire` and `aacquire` append a ticket to a priority deque and,
on timeout, raise without removing it. The stale ticket stays at the head of its deque and is
reselected by `_choose_ticket` forever, so every later acquirer at that priority times out.
This is a permanent head-of-line block.

Fix: remove the ticket from its deque on every exit path that does not hand it to
`_can_admit`, in a `finally` guarded by an "acquired" flag. Add a regression test that times
out one acquirer and then proves a second acquirer at the same priority still succeeds.

### 1c. Streaming leaves the circuit breaker in half-open

`src/backstop/transports.py`: the non-streaming path calls `_record_outcome`, which clears the
half-open probe flag. The streaming path never does. After a 503 opens the circuit, a
successful stream leaves the circuit in half-open and the next request is rejected with
`CircuitBreakerOpenError` indefinitely.

Fix: on successful stream setup, record a success outcome. On stream setup failure, record a
failure. Do not wait for the stream to be consumed — record at dispatch, because the purpose
is to release the half-open probe, not to measure stream lifetime. Fix both sync and async.

### 1d. Async transport skips pre-admission checks

`src/backstop/transports.py`: the sync path calls `_pre_admit_checks()` before the hooks. The
async path never calls it, so `rate_limiter`, `agent_guard`, and `shadow_policy` are not
enforced for async clients.

Fix: call the same checks in the async path at the equivalent point. Add a test proving an
async request is blocked by the agent guard.

### 1e. Blocking Redis reconcile on the event loop

`Budget.areconcile` exists but is never called; both transports call the synchronous
`Budget.reconcile` from the async path, which performs synchronous Redis I/O on the event
loop.

Fix: the async path awaits `areconcile`. Fix `areconcile` so it actually uses the async
backend path rather than being dead code. Guard the non-Redis path so it does not pay a
`to_thread` hop when there is no I/O to move off the loop.

## Task 3 — Spend event schema and attribution context

New package `src/backstop/ledger/`.

### `SpendEvent`

A frozen dataclass, one instance per completed provider request. Fields, with types:

| field | type | required | notes |
|---|---|---|---|
| `event_id` | `str` | yes | `uuid4().hex`, set at construction |
| `occurred_at` | `str` | yes | RFC 3339 UTC, microsecond precision |
| `schema_version` | `str` | yes | literal `"1.0"` |
| `provider` | `str` | yes | `"openai"` or `"anthropic"` |
| `model` | `str` | yes | as reported by the caller/response |
| `endpoint` | `str` | yes | normalised, no query string, no api-key |
| `priority` | `str` | yes | `critical` / `default` / `background` |
| `outcome` | `str` | yes | `success` / `error` / `circuit_open` / `budget_denied` / `queue_timeout` / `fallback` |
| `input_tokens` | `int` | yes | `>= 0`, `0` when the provider reported none |
| `output_tokens` | `int` | yes | `>= 0` |
| `cache_read_tokens` | `int` | no | `0` default |
| `cache_write_tokens` | `int` | no | `0` default |
| `latency_ms` | `float` | no | `>= 0.0` |
| `retries` | `int` | yes | `>= 0`, default `0` |
| `estimated` | `bool` | yes | `True` when tokens came from a local estimate, not provider usage |
| `attribution` | `Attribution` | yes | frozen dataclass, below |
| `cost` | `CostBreakdown \| None` | no | `None` when no price is known |
| `request_id` | `str \| None` | no | provider request id when available |

Validation in `__post_init__`: non-negative token counts, non-negative latency, known
`priority`, known `outcome`. Raise `ValueError` on violation. The event is immutable.

### `Attribution`

Frozen dataclass of optional strings, all defaulting to `None`:
`team`, `agent`, `session`, `task`, `feature`, `surface`, `customer`, `tenant`,
`environment`, `repo`, `cost_center`, `gl_code`, `currency`.

A method `merge(base, override)` returning a new `Attribution` where any non-`None` field in
`override` wins. Never mutate.

### Attribution propagation

Use `contextvars.ContextVar` holding a frozen `Attribution`. A single module-level default of
`Attribution()`.

Public API, exactly these three forms:

```python
from backstop import attribution, with_attribution, current_attribution

# 1. context manager, scoped
with attribution(team="payments", feature="checkout-v2", customer="acme"):
    client.chat.completions.create(...)

# 2. decorator, for a function or method that makes calls
@with_attribution(agent="refund-bot")
def handle_refund(ticket): ...

# 3. read it back
current_attribution()
```

Nesting must merge: the inner scope wins on conflicting fields and restores the outer value on
exit, including when the body raises. Because it is a `ContextVar`, it propagates correctly
across `asyncio` tasks and thread-pool submissions that copy context, which is the behaviour
we want. Document that a raw `loop.run_in_executor` call does **not** copy context and needs
an explicit wrapper.

No call site is rewritten. Existing code keeps working with an all-`None` attribution.

## Task 4 — Price catalog and cost

New `src/backstop/pricing_catalog.py`.

### Catalog

A `PriceEntry` frozen dataclass: `model`, `provider`, `input_per_mtok_usd`, `output_per_mtok_usd`,
`cache_read_per_mtok_usd`, `cache_write_per_mtok_usd`, `effective_from`, `source`, `confidence`.

A bundled static table covering the models the repo already references plus the common current
ones, with `source="bundled"` and `confidence="list"`. No network access at import. No remote
fetch on the hot path. Ever.

### Precedence

Highest wins:

1. explicit per-call `price_overrides` passed to `compute_cost`
2. user-supplied catalog file (`config.price_catalog_path`), `source="user"`
3. bundled table, `source="bundled"`

A `PriceCatalog` object resolves a `(provider, model)` to a `PriceEntry` or `None`.

### Unknown price

`compute_cost` returns `None` and the event is recorded with `cost=None` and a
`price_unknown` counter incremented. It never guesses and never uses a default price. Finance
trust requires that a missing price is visible, not silently filled.

### `CostBreakdown`

Frozen dataclass: `input_usd`, `output_usd`, `cache_read_usd`, `cache_write_usd`, `total_usd`,
`currency` (literal `"USD"`), `price_source`, `estimated_tokens` (bool). All money values are
`Decimal`, quantised to 6 decimal places with `ROUND_HALF_UP`. Never binary floats for money.

### Accuracy

`compute_cost` is pure and deterministic given the same inputs. A test asserts that a known
model with known usage produces an exact expected figure to the 6th decimal place.

## Task 5 — Ledger sinks

New `src/backstop/ledger/sink.py`.

- `LedgerSink` — a `typing.Protocol` with `write(event: SpendEvent) -> None` and
  `flush() -> None` and `close() -> None`.
- `NullSink` — discards. The default when the ledger is disabled.
- `MemorySink` — bounded ring buffer, `maxlen` configurable, default `10_000`. This is what
  `backstop ledger demo` and the unit tests read.
- `JsonlSink` — append-only NDJSON, one JSON object per line, `os.fsync` optional and off by
  default. Creates parent directories. Never raises into the request path: a write failure
  increments `sink_errors` and is swallowed.
- `BoundedWriter` — the hot-path component. Owns a `queue.SimpleQueue` drained by one daemon
  thread, with a bounded `collections.deque` used as the buffer so `put_nowait`-style
  behaviour is explicit. On overflow: drop the event, increment `dropped_events`, never block,
  never raise. The transport calls `writer.submit(event)` and returns immediately.

Threading: exactly one drain thread, started lazily on first submit, `daemon=True`, joined on
`close()` with a bounded timeout so shutdown cannot hang. Test that 10,000 rapid submits with a
slow sink do not block the caller and that `dropped_events` is accurate.

## Task 6 — Transport integration

Config additions on `BackstopConfig`, all defaulted so existing behaviour is unchanged:

- `ledger_enabled: bool = False`
- `ledger_path: str | None = None` — when set, writes NDJSON
- `ledger_memory_events: int = 10_000` — when `ledger_enabled` and no path, keeps a memory ring
- `price_catalog_path: str | None = None`
- `detection_enabled: bool = False`

`BackstopState` gains `ledger` and `detector` attributes, built by a `BackstopState.create`
factory method so tests and the CLI build them the same way. Both default to `NullSink` and a
disabled detector.

In `BackstopTransport`, after the existing non-streaming reconcile block, build a `SpendEvent`
from the request context, the response usage, and `current_attribution()`, then
`self.state.ledger.submit(event)`. For streaming, build the event with whatever usage arrives
and submit it as the stream is set up.

The submit call must be non-blocking. The transport must not open a file, must not do network
I/O, and must not take a lock that a sink could hold. A regression test asserts the transport
completes with a deliberately stalled sink.

Fix the audit finding that `_observe_gauges` re-reads the ContextVar instead of the resolved
tenant while we are in this code.

## Task 7 — Chargeback export and CLI

New `src/backstop/ledger/export.py`.

`build_chargeback(events, group_by, period, currency="USD")` returns rows. Default grouping is
`("team", "feature")`. Each row: the group keys, `request_count`, `input_tokens`,
`output_tokens`, `cache_read_tokens`, `total_usd`, `currency`, `unpriced_requests`, and
`first_seen` / `last_seen` RFC 3339. Rows are sorted by `total_usd` descending. Money is
emitted with exactly 2 decimal places as strings, so a spreadsheet never reinterprets it.

CSV writer: RFC 4180, UTF-8, stable column order, newline at end of file. A `revenue_join` helper
that emits a second CSV keyed on the same group keys, so finance can join cost to their own
revenue without us becoming a revenue system.

CLI, added to the existing `argparse` dispatcher in `src/backstop/cli.py`:

- `backstop ledger demo` — keyless, offline, prints a markdown chargeback table. This is the
  pitch artifact. It must be deterministic.
- `backstop ledger show --path FILE [--limit N] [--json]`
- `backstop ledger export --path FILE --out FILE.csv --group-by team,feature`

`demo` must be deterministic to the dollar, which means it uses the bundled catalog and fixed
synthetic events, not live provider data.

## Task 8 — Runaway-spend detection

New `src/backstop/detection/`.

`SpendSignal` computed per submission, cheaply, in-process:

- `cost_velocity_usd_per_min`
- `tokens_per_request` rolling mean
- `input_token_growth_ratio` vs the rolling baseline
- `retry_ratio`
- `distinct_model_ratio`

`RunawayDetector` holds a bounded deque of recent events per attribution key and evaluates:

1. **velocity** — rolling cost/minute above `velocity_threshold`
2. **drift** — `tokens_per_request` above `baseline_multiplier` x the rolling median
3. **retry amplification** — `retry_ratio` above `threshold`
4. **context growth** — `input_token_growth_ratio` above `threshold`

Each fires a `DetectionSignal(kind, severity, key, observed, threshold, detail)`.

**Shadow mode first.** `DetectionConfig(shadow=True)` records what it *would* have blocked and
blocks nothing. This mirrors the existing `ShadowCollector` and is required by the plan. A test
proves a shadow detector never blocks while still producing signals.

Auto-kill is **not** in this build. The plan's Area B requires a resumability and idempotency
design before anything is killed mid-flight, and shipping an unresumable kill switch to save
time is exactly the kind of decision the plan says to refuse. The detector reports; it does not
kill. Say so in the docstring and in `docs/planning/04-detection-design.md`.
